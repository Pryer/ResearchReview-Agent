# 有界全文分块抽取

启用 LLM 卡片抽取时，全文路径不再只读取前 8,000 字符：

```text
已有解析页面（无页面时使用 full_text）
→ 页内章节、段落边界切块
→ 可选字段级 BM25/dense/RRF/重排，结合章节覆盖选择块
→ 每块一次多字段原文摘录
→ 连续原文及位置校验
→ 去重聚合 PaperCard
→ 原有字段质量门禁、主张授权与引用验证
```

## 范围与预算

- `CARD_EXTRACTION_CHUNK_CHARS=6000`：每块字符上限，可配置 1000–12000。
- 页内长章节使用 400 字符重叠，不跨章节或页面拼接。
- `CARD_EXTRACTION_MAX_CHUNKS=8`：每篇最多八次块抽取调用，可配置 1–32。
- 每次调用同时提取多个字段，每字段最多三段、每段 15–1000 字符的连续原文。
- 按章节轮转选择；混合模式同时使用字段检索结果。识别到参考文献标题后排除该章节。
- 所有调用仍受既有共享 token、截止时间与取消边界约束。
- 普通来源失败停止该论文后续块调用，保留此前成功摘录；预算、取消及执行失效信号向上传播。

长度单位是字符，不是模型 tokens。调用上限不保证费用恒定；已有预算账本仍是最终边界。
未启用 LLM 时仍走原规则抽取路径。

## 第二层字段检索

第一层继续以标题、摘要和关键词筛选候选论文。第二层只接受同一篇论文的 Chunk，
不得混入其他论文，也不会自动为检索命中授予引用权限。

`CARD_CHUNK_RETRIEVAL_MODE=hybrid` 时，为研究问题、方法、数据、指标、结果、贡献、局限
七个字段分别执行 BM25 与 dense 召回、RRF 融合和可选专用模型重排，每字段返回 Top-K。
原文向量只构建一次，所有字段共用单篇论文内的 NumPy 精确归一化向量索引。
向量缓存复用现有 VectorCache，按模型、端点、维度、缓存版本、文本类型及内容指纹隔离。
默认不新增 FAISS 或向量数据库服务；可显式启用独立 pgvector 后端。
持久化、来源 CAS、迁移和验证边界见 [知识工程与三模块工作流](knowledge-engineering.md)。

默认最多 128 块参与索引；按章节轮转并保留长章节尾块，达到上限时记录 `index_truncated`。
每字段默认 Top 5、重排窗口 12；Embedding 按既有客户端批量请求，重排最多七个字段窗口，
均沿用共享请求、token、重试、截止与取消预算。第二层会增加模型调用，不承诺节省费用。

默认八次抽取额度的一半先给章节覆盖（方法、结果、局限等），剩余按字段命中名次轮转，
不足时继续从未选章节补齐；同一块只抽取一次，每次抽取多个字段，避免重复读取共享上下文。
`field_hits` 表示检索候选，`selected_chunk_ids` 表示抽取计划，`chunks[].status` 才表示
实际处理情况。三者不能等同；Top-K 不表示全部命中已被阅读，也不表示全文覆盖。

Embedding 失败保留 BM25 与章节选择；重排失败保留 RRF 顺序，并记录脱敏 `degraded`。
卡片附加质量问题，不能标为 `valid`。取消或预算信号直接停止，不继续降级调用。
默认 `sections` 模式不调用 Embedding 或 Reranker；它使用同一章节选择机制。

启用第二层需安装 `requirements-retrieval.txt` 并配置已有 Embedding/Reranker 端点与密钥，
另设置：

```dotenv
ENABLE_LLM_CARD_EXTRACTION=true
CARD_CHUNK_RETRIEVAL_MODE=hybrid
CARD_CHUNK_TOP_K=5
CARD_CHUNK_INDEX_LIMIT=128
CARD_CHUNK_RERANK_WINDOW=12
CARD_CHUNK_ENABLE_RERANK=true
```

配置示例不触发运行，本次开发保留当前本地开关，未调用真实 Provider。

## 位置与证据

Chunk 不重新清洗来源文本。`offset_basis=page` 时，字符区间相对于
`parsed.pages` 中对应页的 `text`；无页面文本时为 `full_text`。区间采用左闭右开。
块不会跨页，一条证据只对应一个页面。解析器与切块器共享章节标题规则，支持小节编号和冒号。
章节标题仍使用有限正则识别，未识别部分保留当前章节或
`full_text`，不能声称可靠恢复了 PDF 的全部章节结构。

摘录先与当前块逐字比对，再映射回来源位置；绑定证据前再次回读验证。有效摘录直接进入字段
候选，避免被旧路径最多 200 条候选、20 条证据的采样限制排除。每段原文独立形成字段声明，
多个块的不同发现均保留，不通过额外模型调用消解冲突。

连续原文校验只证明内容存在，不能单独证明字段分类、实验条件或综述主张正确。
现有访问门禁、质量门禁与后续主张验证仍须执行。原文摘录暂不翻译为中文。

## 覆盖状态

卡片 `extraction_coverage.chunks` 保存每块位置和处理状态，不保存提示词或错误详情：

- `processed`：收到符合字段数组协议的抽取响应；字段可以为空。
- `failed`：块调用或响应协议失败，原因仅保存异常类型。
- `skipped`：达到调用上限，或此前发生来源失败。
- `excluded`：识别为参考文献章节，明确排除。

`complete` 仅表示可用解析文本的所有非排除块均被处理，**不表示 PDF 解析完整、没有 OCR
缺失、字段信息完整或主张正确**。否则状态为 `partial`，卡片保留
`extraction:partial_coverage`，质量状态不能为 `valid`。
无支持字段保持空值，不因字段为空而用规则抽取填回整篇文本；非法摘录被拒绝并记录质量问题。

摘要与 CNKI 摘要路径维持原协议。历史卡片的 `extraction_coverage=None`，不能据此推断
其全文已被处理。历史 EvidenceSpan 的 `offset_basis=None` 保持兼容。

## 验证边界

离线测试覆盖后半篇结果与局限、位置回读、字符覆盖、重叠、调用上限、来源失败、非法数值摘录、
空输出、序列化兼容、参考文献排除与停止信号。
第二层测试另覆盖无词项匹配的受控语义召回、字段 Top-K、重排、缓存与内容/模型失效、
论文隔离、索引上限、后部章节选取、模型故障降级及通过抽取链路生成带位置的字段声明。
测试不证明真实模型字段完整率、语义准确率、费用收益或 PC01 正文成功；本轮未追加真实 Provider 验收。
