## 优先修复的可复现边界

### A. 历史卡片自证：P0

`verify_claims._card_evidence()` 在没有 EvidenceSpan 时，把研究问题、方法和结果字段重新包装为来源证据。
合成卡片声明 full_text 但不提供任何原文 span，结果字段与待验主张一致；一个始终返回 entailed 的语义替身可将其判为 supported。
这证明数据路径没有区分独立原始证据和抽取结果，不能解释为真实 LLM 已误判或整套 Agent 必然发布错误。
修复应从来源资格入手：缺少可信原文的字段只作历史摘要，不进入完整原文核验和正文授权；不能让 LLM 自行补证明。

### B. DOI 冲突的标题合并：P0

两条标题相同但 DOI、作者和年份不同的合成记录，经 `deduplicate_papers()` 返回一条。
应增加强标识冲突及版本关系判定，阻止弱标题路径覆盖强冲突，并测试不同来源的真重复闭包保持成立。

### C. 否定字段被标为明确：P0

原文为 “We use a dual encoder method for document retrieval.”；字段为同句增加 “do not”。
直接调用证据绑定后，method 的 explicitly_reported=True。
该标签不能再由词项重合单独授予；原文定位、候选相似度与语义支持需分开。后续 LLM 可能纠正，不能据此容忍上游误授权。

### D. 额外发现：语义核验证据被截断，P0/P1

`_verify_review_claims_legacy()` 构造 evidence_snippets 时每段先截到 360 字符，
`_llm_entailment_results()` 再取 500，因此语义模型实际拿到的仍最多是 360。
合成 784 字符原文包含末尾的统计显著性与样本限定，捕获到的核验提示词不含该限定。
这证明上下文丢失，不证明真实模型最终会作何判定。
应分离 UI 展示摘要与核验原文，保留完整受控证据或能回读的相关上下文；预算不足明确待验，不能静默切掉条件。

- processed/complete 表示处理覆盖；partial 不代表已核验的每条证据都为假。目前覆盖不足限制整体 valid 是保守策略，不宜直接删除。
