# v2产品投影：HTTP轮询、终态聊天与草稿下载

## 修复范围

1. 原execution_progress以“已经执行过专业委派”为v2识别条件。主控首次澄清或提前停止时没有专业动作，前端回退显示固定步骤进度。现Job绑定记录当次任务配置的架构版本；无专业动作也可返回v2零计数，旧绑定继续通过实际委派事件兼容识别。
2. 工具结果未知已由真实接管流程记录，底层归属没有改动。轮询原来只统计完成、失败与待确认，遗漏uncertain，前端又省略失败计数。现失败、结果未知和待确认分别展示，终态也不再显示崩溃残留running动作对应的活动角色。
3. 原聊天结束处理在取消/失败时仅保存停止说明，轮询阶段可读的已发布草稿随active_job清理而消失；普通结果元数据也丢弃了下载所需的交付/发布字段。现使用统一的纯投影函数保存已发布版本及其引用、核验状态和下载标记，停止原因继续保留。失败结果中的未发布候选不作为交付来源，澄清问题仍保留在消息中。

正文发布、候选隔离、Check与引用门禁、预算、费用和提交路径没有改变。新增投影不签发发布授权，不把“有草稿”改成“执行成功”或“满足正式要求”。

## 验证路径

- 12项纯消息投影检查：取消/失败/阻断/澄清与旧草稿共存，原输入不变，未发布候选隐藏，下载需要发布标记和非空正文，空answer按实际终态给出说明。
- 进度新增5项：v1/v2首次委派前的冻结配置、真实acquire接管补写uncertain、终态残留running动作、失败工具；原4项继续覆盖执行owner隔离和失败动作无伪造提交版本。
- 3项实际产品链：生产Controller发布合成草稿并保存较新私有候选，实际GET /api/reviews/jobs轮询SQLite，真实Streamlit AppTest执行聊天完成处理和消息渲染；取消/失败/澄清均保留原发布正文、停止状态及草稿下载控件，澄清仍提示输入。
- 接管后重新冻结原报告，核对工具结果仍为uncertain且不混入新执行的成功工具。没有为展示另建事件归属规则。

最终专项：**82 passed，22.03秒**，日志data/v2_product_targeted_tests.txt。全量`python -m pytest -q --tb=short`：**2702 passed、17 skipped、11 warnings，397.11秒**，日志data/architecture_v2_product_full_tests.txt。`git diff --check`和本批Python编译检查通过。

## 收敛与边界

聊天终态统一调用job_presentation，移除旧分支重复代码；下载条件由同一函数用于组件与专项检查。对外状态沿用已有业务字段，工具账本与接管逻辑保持原实现。架构配置在Job绑定时读取任务设置，不随进程后续配置漂移。时序和授权边界保留中文WHY说明。

AppTest运行实际Streamlit控件树，未进行真实浏览器像素检查。材料来自合成测试夹具；无真实来源/LLM/CNKI、原生pgvector或人工质量审查，不声明模型效果或线上可用性。本批不覆盖所有历史任务格式和完整产品入口，S4继续推进；默认架构仍为v1。
