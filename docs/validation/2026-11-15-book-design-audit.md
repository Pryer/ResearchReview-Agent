## 结论

项目的总体架构适合证据驱动的文献综述：受约束的 Main 动态决策、按角色和动作隔离的执行、两层混合检索、证据到主张的授权、独立 Check 与确定性提交组成了完整闭环。现有实现与书中强调的 Harness、渐进披露、管理者协作及可恢复执行原则相符。

优先工作是补齐现有边界，而非再增加角色或换框架：下载网络出口、核验缓存的执行身份、下载中的取消，以及诊断文本脱敏。质量侧最缺的是独立的完整任务评测，而非更多同源自审。书中的通用执行器、MCP、语音、机器人、RL 和自动进化均有适用条件；它们不是本项目必须补齐的功能清单。

本次做逐章设计原则审查，并对直接相关小节、十章配套实验索引与项目生产调用链交叉核验。未运行书中 109 个实验，未逐行审计其全部配套代码。下文“书中原则”与“针对本项目的工程判断”分别标识，书中案例的成绩不移植为本项目成绩。

## 一条需求下的实际责任链

例：用户要求“2022—2025 年开放域问答中的 RAG 综述，至少引用五篇论文”。

1. 入口解析主题、年份、交付物与最低唯一引用数。原请求和显式约束成为权威任务状态。
2. Main 读取五字段视图，在当前合法动作内规划。必要恢复与依赖由代码给定，剩余选择交给模型。
3. `SubagentLoop` 接收一次委派；`AgentController.execute` 绑定目标、预算、幂等身份及输入版本。
4. `BaseSubAgent.execute` 用 `build_task_state` 生成按动作输入契约深拷贝的工作状态。节点 Handler 组合底层工具执行。
5. Search 的 `fetch_metadata` 在 PDF 流水线启用时负责全文下载、解析；Analysis 再做块检索、证据抽取、路线分析与主张授权。文件位置与职责由调用链决定。
6. 每次动作完成，经白名单和状态基准校验提交业务产物，再交回 Main。专业角色的建议只作为下一轮规划输入。
7. Writing 生成候选。严格路径委派 Check 核验当前正文与证据，再申请结束；草稿优先路径按专门预检公开草稿，随后继续核验或修订。
8. 最终输出按发布状态读取获准产物，保留正文与实际质量等级的对应关系。

代码入口：[main_loop.py](../../tests/reference_v1/main_loop.py)、[subagents/loop.py](../../tests/reference_v1/subagent_loop.py)、[controller.py](../../app/agent/controller.py)、[task_context.py](../../app/agent/task_context.py)、[graph.py](../../app/agent/graph.py)、[delivery.py](../../app/agent/delivery.py)。

## 应保留的设计及准确边界

| 设计面 | 已实现机制 | 当前适用范围与取舍 |
| --- | --- | --- |
| 动作与契约 | ActionSpec 管参数、角色及粗粒度依赖；ActionContract 管实际状态输入/输出；工具目录由注册表派生 | Action 是一次授权的业务操作，可以包含多个节点与远程调用。业务状态提交可原子化，远程调用与文件写入各自管理副作用。 |
| 动作暴露 | MainPolicy 默认构建稳定的全量动作目录，状态栏给当前 allowed_actions，返回后再验证 | 当前并非每轮只发送合法动作的 Schema。固定目录有前缀复用价值，运行时准入仍在模型输出后强制执行。未来对照两方案应同时量化协议错误、输入量与缓存。 |
| 双层投影 | subagent_context 构造模型视图；build_task_state 为实际 Handler 构造契约工作副本 | 模型看到什么与 Handler 能提交什么分别受控。Python 同进程字段契约适用于可信 Handler，插件或恶意代码需要进程/容器及凭证隔离。 |
| 角色生命周期 | 角色轨迹各自维护，一次委派限一个研究动作；完成后返回 Main | 不是自由互调的 Agent 网络。默认确定性子动作执行可省去一次局部选择模型请求；仍保留子循环和汇报语义。 |
| 工具身份 | 协议层 Tool 是 Action 的调用表示，app/tools 是具体能力函数 | 底层函数可能有网络、文件、缓存和模型副作用。它们应按风险和生命周期管理，并非统一的纯函数。 |
| Check 与提交 | 受保护字段阻止 Check 修改正文/卡片/授权；报告绑定输入；Controller 负责候选结算与回滚 | 独立的是动作、上下文和提交权限；当前 for_agent 复用同一模型服务。书中的“独立视角”要求用实际原文、规则及外部审查提供新信息。 |
| Sidecar | 狭窄上下文只读审查动作参数，失败升级，控制异常透传 | 默认关闭，且复用传入服务；不应称为已运行的异源模型双签。其建议仍受确定性授权约束。 |
| 状态栏与轨迹 | epoch 内保持追加式前缀，压缩时归档并重建，保留调用/结果配对与最新目标 | 旧状态累积是可测的成本项，不是自动判错。末尾替换同样只会使变动点以后的前缀失效，不能宣称全部缓存必然清空。 |
| 大产物与回查 | 资料按类型与作用域外置，工作窗口留摘要，近期持久化任务结果限 16 条 | 完整结果从持久任务查；研究状态其他集合仍有各自的复制/序列化成本。Artifact 外置并不自动让整个运行状态变为常数大小。 |
| 两级 RAG | 候选论文元数据与单篇全文块分别排序，BM25/Dense/RRF/精排组合，七字段与八块预算分开 | 属于文档范围与证据粒度的两层检索；不是 RAPTOR 摘要树或 GraphRAG。单篇精确 pgvector 排序当前有理由，性能按实际负载判断。 |
| PDF 溯源 | 页级清洗文本、分块坐标、空白映射、逐块错误隔离与字段支持 | 坐标锚定到解析文本；双栏阅读顺序、复杂表格与 OCR 需要独立能力和原 PDF 审查。对高级版面能力的需求取决于实际失败分布。 |
| 证据与主张 | 来源身份、原文片段、字段资格、主张授权、引用和交付检查相互衔接 | 来源定位与字段语义、主张语义分别评估。末位作者/数据集分组是保守依赖代理，不能证明实验真正独立。 |
| 篇数与篇幅 | 程序统计唯一有效引用，字数/段落按交付契约检查 | 目标字符区间含软告警，背景硬规格当前为 3—5 段。任意用户指定段数是否硬验收，应由具体结构契约决定。 |
| 恢复与费用 | Owner、版本、取消、数据库执行时钟及租约保护提交；调用预留与结算记录费用 | 保证合法结果提交与账本连续，无法撤销已发生远程执行。相同任务恢复沿用累计费用，新研究工作计数另有代次边界。 |
| 双库 | 向量 Building/Active 与业务 CAS 及指纹复用衔接，防护令牌拒绝迟到构建 | 是可恢复的状态机协调；跨库中间态需要检查与恢复，不是两库共同原子事务。 |
| 服务身份 | 非回环部署要求 API Key，业务接口按共享 Key 保护 | 当前适合单机或可信协作部署。向量 tenant 字段和 session_id 提供作用域，不构成面向独立用户的完整租户身份授权。 |
| 记忆 | 会话内摘要与失败回查标为 historical、requires_revalidation、authorizes_evidence=false | 历史帮助规划，当前资格取自权威状态。跨用户记忆、自动经验升级为系统指令不在当前实现范围。 |

## 需要优先处理的四项边界

严重程度以部署条件衡量。以下是当前源码与 mock 探针得到的项目判断，不是照搬书中示例。

### F1｜对外部署前：将开放获取判断与下载网络出口分别收紧

**对应原则：** 第 4、5 章的执行前验证及信任边界下移；第 3 章的来源可信度。

**代码：** [download_pdf.py](../../app/tools/download_pdf.py) 的 `is_open_access`、`download_open_access_pdf`。

**当前事实：** 开放获取判断中包含对整个 URL 的 `arxiv.org` 子串匹配；下载把元数据中的地址直接交给 HTTP 客户端，并开启自动重定向。该处没有目标 IP、主机及重定向逐跳出口校验。

**已做探针：** mock 完整拦截 HTTP 请求，确认“标记开放获取但目标为回环”的合成元数据能够到达 HTTP 客户端；包含 arXiv 字符串的错误主机名被开放获取判断接受。探针实际网络请求为零。

**触发条件与影响：** 上游元数据、用户导入材料或开放地址的重定向落点可被操纵，且服务能访问内网时，存在 SSRF 与来源资格混淆风险。本次未证明公网 API 存在无需认证的端到端利用链。

**建议：** 解析规范主机名并精确判断可信仓储；OA 授权和网络可访问策略独立实现。只允许预期协议，拒绝回环/私网/链路本地及云元数据目标，逐跳复核重定向，部署层设置出网策略。处理 DNS 重绑定时应把验证与实际连接目标绑定。继续保留来源访问政策和下载体积限制。

**验收：** 合法开放 PDF 保留通过；伪主机、私网地址、公开地址跳入私网和跨协议跳转全部在发请求前拒绝，诊断能说明拒绝原因。

### F2｜切换核验模型或提示词时：验证身份进入缓存与报告

**对应原则：** 第 3 章的知识版本、第 7 章的受控比较、第 9 章的更新可归因和可回滚。

**代码：** [checking.py](../../app/agent/checking.py) 的 `check_input_fingerprint`；[verify_claims.py](../../app/tools/verify_claims.py) 的 `_entailment_fingerprint` 与语义缓存读取。

**当前事实：** 指纹覆盖正文、证据、任务约束、验证器版本、阈值和上下文限制，但没有绑定实际核验模型/Provider、核验提示内容身份与实际执行时的模型回执。语义缓存复用依据主张和证据指纹。

**已做探针：** 仅替换配置中的合成模型名、保持正文和证据不变，Check 输入指纹保持不变。未调用真实模型。语义缓存缺失模型身份由代码检查确认。

**触发条件与影响：** 跨部署升级模型、切换供应商或修改核验提示后，旧报告可能仍被视为当前报告，旧语义判定也可能被复用。它不使旧证据自动错误，但会让“已由新验证器复验”的边界不成立。

**建议：** 定义版本化 verifier profile，包括提示哈希、模型、Provider、影响语义的参数及规则版本；报告保存实际执行 profile 和回执身份。模型 fallback 时保存实际身份；预期 profile 与可接受兼容策略应明确。同步纳入 Check、语义缓存和公开版本复验规则。

**验收：** 模型、提示或阈值变化触发相应失效；只变调度日志不失效；fallback 的实际来源可追溯。保留 same-profile 缓存命中测试。

### F3｜长文件下载：让取消和总期限进入流式处理安全点

**对应原则：** 第 5 章的终止路径、第 6 章的安全点和取消语义。

**代码：** [download_pdf.py](../../app/tools/download_pdf.py) 的单篇下载和 `batch_download_pdfs`。

**当前事实：** 批量层在提交前和 `as_completed` 返回一个 Future 时检查取消；单篇请求设置连接/读取超时及最大字节数，但流式循环没有协作取消/执行期限检查。线程池上下文退出会等待已经启动的请求结束。

**触发条件与影响：** 慢速但持续有数据的下载，可能长期不触发读取超时；用户取消后资源继续占用，线程池退出也可能等待。Controller 的提交门禁仍可拦下取消后的业务提交，因此应区分“业务状态安全”与“及时停止资源消耗”。

**建议：** 为单篇调用传递取消/期限上下文，在请求前、分块写入和退避等待检查；批量等待采用有检查机会的等待循环，限制在途提交量。按清晰的缓存策略清理未完成文件。解析等不可抢占步骤如需严格硬期限，再评估独立进程。

**验收：** 无数据返回、慢速持续流、取消发生于下载中和重试等待中均有有界收敛；未完成文件不作为有效缓存；已合法完成文件按既有规则复用。

### F4｜诊断报告：结构化凭证过滤扩展到自由文本

**对应原则：** 第 3 章的日志隐私、第 5 章的私有数据与外部通信风险、第 7 章的隐私感知观测。

**代码：** [execution_report_collector.py](../../app/services/execution_report_collector.py) 的 `safe` 及报告导出路径。

**当前事实：** 已过滤 api_key、authorization、password 等键和 reasoning 字段；普通字符串按原文返回。报告捕获请求、决策、上下文和部分错误，因此自由文本也属于数据出口。

**已做探针：** 合成 `api_key` 字段被删除；嵌入普通 error 字段的合成 Bearer 字符串保持原样。没有读取真实密钥。

**触发条件与影响：** 用户误把凭证写进需求，或异常字符串含认证信息时，诊断导出可能保留它。API Key 已保护业务接口，风险仍存在于下载、分享和长期保留报告时。

**建议：** 日志/报告入口统一处理确定的敏感模式与字段 allowlist，为凭证、个人信息和研究内容采用不同保留策略。保留定位所需的脱敏错误类型、来源域与哈希。脱敏规则同时测误删，避免移除论文 DOI 和实验数值。

**验收：** 结构化、嵌套及自由文本中的合成凭证均被遮盖；普通论文文本和数字不被误改；报告失败继续不影响研究结果。

## 合理但需要实验决定的设计

### 状态栏：当前追加式可以保留

第 2 章明确承认追加和替换两种策略。当前 `ReActContext.request` 保持 epoch 内旧前缀，压缩时归档重建，符合追加方案。项目已经有合成体积对照，但它没有实际 Provider 命中和计费数据。

下一步在同一任务、同一模型和质量标准下比较：每轮状态大小、保留轨迹、缓存命中 Token、实际费用、压缩次数、对过期状态的错误引用和最终达标率。替换前保留报告捕获与崩溃恢复语义。不要仅按字符或估算上界决定生产策略。

### 四角色：保留权限分工，验证额外调用是否有价值

书第 10 章的核心判断是协作带来什么新信息。Search 获取外部材料、Analysis 形成来源绑定、Check 执行可回读证据和独立规则，均有明确用途。当前 LLMService 的角色绑定只换提示与能力目录，共用模型服务；因此先对照 Check 的规则、原文和语义判断贡献，再考虑异源模型。

建议比较“单规划器加受控工具”“当前四角色确定性执行”“开启子角色模型决策”三组。在相同材料、总预算和门禁下统计达标率、引用错误、恢复量、调用和时间。无需为了角色形式增加一轮模型选择。

### 检索与 PDF：先修覆盖损耗，再增加知识结构

论文层和证据层的粒度符合任务需要；RRF 的去重范围与族数缩放也有清晰语义。单篇快照精确检索和默认八块抽取都是当前可解释的基线。研究员需要的跨页表格、双栏顺序和遗漏证据，应通过原 PDF 的字段审查判断优先级。

如果失败集中在块上下文丢失，可以比较父级章节回取或上下文前缀，并同时检查原文锚点。若失败集中在关系推理，再评估 GraphRAG。增加 RAPTOR、知识图谱或 ANN 需要对应失败和收益证据。

### 当前部署边界：单机可信协作

进程内限流、线程池接纳、SQLite 单写者和共享 API Key，与单机研究工具相匹配。若扩展独立用户服务，再补用户主体绑定、会话和 Artifact 逐对象授权、服务端租户注入、总配额协调、隔离 Worker 及清理策略。数据库中的 tenant 列是实现基础，并非产品已完成多租户授权的证据。

## 评测闭环应怎样补齐

已有的 [benchmarks.md](../benchmarks.md) 能复现固定池排序、简单引用/数字受控错误和卡片复用。其用途明确，但自然候选稿的 Citation Precision / Faithfulness 仍待独立审查；回归数量也不衡量模型在新需求上的成功率。

1. 先构建十余个固定研究任务，覆盖纯检索、严格综述、草稿、修订、证据不足、来源失败、取消恢复与不改约；包含“应成功”及“应拒绝/阻断”两类任务。
2. 从真实失败状态提取轨迹前缀：例如 Partial 卡片、写作后待核验、核验失败待修复和预算接近软阈值。答案定义为可接受动作集合及禁止动作，实际调用决策模型评估。
3. 原文审查优先 method/results 等关键字段，记录 PDF 版本、摘录与字段；引用按关联对判定，事实忠实度按可审查原子主张判定，报告拒答和交付覆盖。
4. 配对评测同任务、同材料、同门禁、同预算，多次运行。报告严格达标率、草稿可用率、连续多次通过情况、费用和墙钟延迟，保留失败与未完成项。
5. 用边界集验证修复目标，用保留集验证原任务；模型、Prompt、政策或索引变更后重跑对应集合，再决定是否扩大实验规模。

第 8、9 章的演进顺序可以据此落地：先让轨迹可评价，再人工提出版本化局部修复，必要时生成候选 Prompt/Skill；独立验证、审批与回滚成熟后，才考虑自动发布或模型训练。运行经验保存为待验证知识，不直接升级为新权限或系统指令。

## 本轮验证与后续顺序

本轮定向运行 13 个测试文件：动作契约、Sidecar、委派上下文、ReAct、Controller、Check、走查回归、投影缓存、全文抽取、Hybrid、评测脚本、持久化运行时及总预算。结果 **214 passed、11 warnings，28.22 秒**。警告来自第三方依赖弃用。上述测试使用替身；未运行真实 LLM、CNKI 或 PostgreSQL 环境。

额外无网络探针确认 F1、F2、F4；F3 为调用链和线程退出语义的静态结论，尚未做真实慢流或取消延迟测量。探针不构成端到端攻击测试。
