# v2 四角色与任务级 Main 接入记录

日期：2026-11-17，Asia/Singapore。对应 plan.md 的 S1—S4 实施进展。

## 已实现的执行路径

```text
TaskMainLoop → delegate_agent → 服务端 Grant
  → DelegationRunner → ActionExecutor → 共享 Controller/业务 Handler
  → 单 Action 提交 → 刷新准入与验收 → 继续或交权
  → 委派汇总 → Main 观察和活动标记清理同快照
```

- 四角色、八个 Profile 使用同一 Runner 与 Action 提交内核；Main 通过任务工具委派，不向模型暴露专业 Action 作为主控工具。
- Search/Analysis 支持确定性与局部 ReAct；Analysis evidence_build 另接真实模型 plan_and_act，使用有界步骤清单、最多两次规划、逐步准入。规划调用走既有 LLM 预算链路。
- Native Tools 不支持时降级 JSON；格式、动作和参数错误仅在配置次数内纠正。取消等控制异常原样传播。
- Writing/Check 的 direct 路径不产生额外局部规划调用。章节修订绑定已知、获准章节，单 Action 最多三章。
- Analysis 验收当前主张对应的作者原述证据与强度；虚构证据 ID 不能满足阶段验收。Check 继续独立执行并绑定当前版本，正式结束由原 finish_validator 裁决。
- 必做恢复动作通过服务端精确 single Grant，参数不由模型改写；跨任务无进展受全局轮数与业务摘要约束。
- 新 Invocation 读取最新业务版本；已持久 Invocation 的身份与输入不在恢复时改写。策略模式随委派持久化，禁止恢复中悄然更换。
- Main 记录任务级决策与五字段报告捕获；完整委派/Action/Tool 报告展示尚未接齐。

## 根因回归

1. **计划游标确认窗口**：Action 已提交、计划游标尚未确认时中断。恢复读取持久结果，推进原计划而非再次执行首步。
2. **Main 观察窗口**：委派结果先持久化，再将结果观察和活动标记清理共同快照。分别在最终快照提交前、提交后中断，重开任务后专业动作均只执行一次，Main 调用保持配对。
3. **错误分类**：仅授权拒绝进入请求修正；Handler 的 ValueError 不再被吞作模型请求错误并重复执行。
4. **配置恢复**：进程开启 v2 不改变旧任务未声明架构字段的解释；累计费用和原用户约束继续保留。
