## 真实运行驱动的修复

1. 委派 scope 在 Schema、提示及服务端校验中明确只接受资源 ID；公开 Profile 目录与每轮状态准入同步，内部 single Profile 不暴露给模型。
2. 纯论文检索不再预留写作收尾额度；总调用、Token、截止时间和取消限制保留。
3. 委派的 unresolved 原因进入有界主控观察，避免只汇报 needs_help 而隐藏缺口。
4. evidence_build 识别已有 reference_coverage 的逐字摘要弱主张契约；只允许单篇、background_fact、abstract_only 和弱化动词，仍拒绝方法/实验/强结论和失配来源。
5. 确定性流程下一步不可用时交回缺口；新 Search Profile 只有必需检索动作可用时才暴露。服务端仍独立验证权限。
6. Main 发布交权在活动 v2 委派期间不抢占 Check 等专业动作；真实恢复已进入语义核验。
7. 发布版本冻结主张核验、证据卡与引用验证；公开结果和聊天投影使用同版材料，历史缺失保持未知。审查导出不再把后续候选的核验套到旧正文上；无绑定核验时按实际交付正文切句，全部保持待核验。
