## 🎯 功能对比

### 旧前端（streamlit_app.py）

❌ **缺点**：
- 每次输入会覆盖之前的内容
- 无法连续对话
- 没有历史记录
- 交互不够直观

✅ **优点**：
- 功能完整，展示详细

### 新前端（chat_app.py）🌟

✅ **优点**：
- 🎯 **ChatGPT 风格**：连续对话，保留历史
- 💬 **多会话管理**：可以同时管理多个研究主题
- 🔄 **实时进度**：显示任务执行进度
- 📱 **简洁界面**：聊天式交互，更直观
- 💾 **自动保存**：对话历史自动保存
- 🎨 **智能折叠**：详细信息折叠在标签页中

## 📊 功能特性

### 1. 连续对话 ✅

**示例**：
```
对话 1: 搜索论文
对话 2: 基于上次结果，生成综述
对话 3: 修改综述的某个部分
对话 4: 添加更多论文
```

每次对话都基于完整的会话历史，无需重复输入上下文。

### 2. 多会话管理 ✅

- 同时维护多个研究主题
- 每个会话独立的历史记录
- 会话间互不干扰
- 自动保存到 `st.session_state`

### 3. 实时进度显示 ✅

任务执行时显示：
```
🔄 running · 正在检索论文
进度 5/14
```

包括：
- 当前状态（queued/running/completed）
- 进度条（X/总步骤数）
- 当前步骤名称

### 4. 智能澄清对话 ✅

当 Agent 需要更多信息时：
```
💬 需要澄清：

你希望这次研究主要侧重哪个方向？
- 技术实现
- 应用场景
- 理论研究
```

用户可以自然语言回答，系统会继续执行。

### 5. 紧凑的信息展示 ✅

- 主要结果直接显示
- 详细信息折叠在标签页
- 只显示关键数据（前 10 篇论文，前 20 条文献）
- 减少滚动和认知负担

## 📝 会话数据管理

### 数据存储

会话数据存储在 Streamlit 的 `session_state` 中：
- 刷新页面会话丢失
- 关闭浏览器会话丢失
- **不持久化到数据库**

### 会话结构

```python
{
    "session_id": {
        "messages": [
            {
                "role": "user",
                "content": "搜索论文",
                "metadata": {},
                "timestamp": datetime
            },
            {
                "role": "assistant",
                "content": "找到 20 篇论文",
                "metadata": {
                    "paper_cards": [...],
                    "claim_verification": {...},
                    ...
                },
                "timestamp": datetime
            }
        ],
        "created_at": datetime,
        "title": "搜索论文"
    }
}
```

### 持久化（可选功能）

如需持久化会话历史，可以添加：

```python
# 保存到 JSON 文件
import json

def save_conversations():
    with open("conversations.json", "w") as f:
        json.dump(st.session_state.conversations, f)

def load_conversations():
    if Path("conversations.json").exists():
        with open("conversations.json") as f:
            st.session_state.conversations = json.load(f)
```

## 🐛 故障排查

### 问题 1：无法连接到 API

**现象**：
```
❌ 无法连接到 API 服务 (http://localhost:8000/api)
```

**解决方案**：
```bash
# 检查后端是否运行
curl http://localhost:8000/api/health

# 如未运行，启动后端
python run_api.py
```

---

### 问题 2：会话丢失

**现象**：刷新页面后历史对话消失

**原因**：数据存储在 `session_state`，刷新会重置

**解决方案**：
- 避免刷新页面
- 或实现持久化功能（见上文）

---

### 问题 3：进度条卡住

**现象**：任务执行进度条长时间不更新

**解决方案**：
```bash
# 查看后端日志
tail -f logs/app.log

# 检查任务状态
curl http://localhost:8000/api/reviews/jobs/{job_id}
```

## 📈 性能建议

### 1. 控制会话数量

- 建议保持 < 10 个活跃会话
- 定期删除不需要的会话
- 避免单个会话消息过多（< 50 条）

### 2. 优化消息展示

- 默认只显示前 10 篇论文
- 默认只显示前 20 条文献
- 详细信息折叠在标签页

### 3. 合理使用轮询

- 任务执行时每 2 秒轮询一次
- 避免同时执行多个任务
