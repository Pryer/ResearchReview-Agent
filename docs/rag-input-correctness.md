# RAG 输入与单篇卡片修复

## 单篇卡片入口

`POST /api/papers/{paper_id}/card` 从论文库取得元数据后，复用 `build_paper_cards` 的
开放 PDF 下载、解析、LLM 抽取、证据门禁和保存流程。没有开放全文时使用摘要；
没有任何可读内容时仍返回不可用于正文的身份记录。论文不存在时保持 404。
模型错误不能变为成功卡片，向量库失败、预算停止和取消继续向上传播。

新增卡片列 `extraction_coverage`，保存处理、跳过及失败块的诊断，并在仓储读取时恢复。
`partial` 覆盖和质量状态不会因数据库往返而丢失；历史记录缺失该字段时保持未知，
不能把空值解释成已读完全文。

已有 SQLite 部署重启服务时通过既有幂等迁移添加该列。新库由 ORM 建表。
若业务数据库使用已有 PostgreSQL（不是独立 pgvector 索引库），需由部署迁移执行：

```sql
ALTER TABLE paper_cards ADD COLUMN IF NOT EXISTS extraction_coverage TEXT DEFAULT '';
```

## 摘要上下文预算

- `PAPER_SCREENING_ABSTRACT_CHARS=4000`：逐篇上限。
- `PAPER_SCREENING_BATCH_ABSTRACT_CHARS=16000`：单批摘要总上限。

实际逐篇额度取逐篇上限与本批总预算均分值的较小者。默认 12 篇一批时，每篇最多
1333 字符；较小的批次允许读取更长摘要。这是字符预算，不是精确 Token 预算，也不包含
题名、协议、JSON 元数据和提示词等开销。

短摘要完整发送，超长摘要保留首尾，在中间加入显式省略标记，标记计入预算。
上下文同时记录原始长度、所选字符区间和截断状态；原始论文摘要保持不变。
提示词要求不得把分离片段当作连续证据，对未提供的条件保持 uncertain。
首尾选择只是一项可解释的有界策略，不保证覆盖摘要中间的全部重要信息。

缓存键包含选择器版本、预算、实际上下文和完整摘要；预算或上下文改变后重新筛选，
不能沿用先前只读摘要前缀的缓存。筛选结果仍受现有完整语义合同与范围门禁约束。

## 有序章节区间

`parse_pdf` 的 `section_spans` 保留顺序、章节族、页码、原文和半开字符区间。
同名章节不覆盖；页面开头没有新标题时延续前一页章节。每页分别记录区间，
不把跨页内容拼成一个无法回读的字符串。空页不产生区间，但原始页码保持不变。

位置相对于清洗后的页面文本，不是 PDF 几何坐标。有序章节与 Chunk 共享标题识别规则；
新增元数据不改变已清洗页面、PDF 哈希或来源指纹。Chunk 主路径继续读取页面，
不会把新增的章节表示当作新的可信原文。

旧 `sections` 字典继续保留最长同类章节及历史名称映射，供现有消费者兼容。
`PaperDetail` 允许携带并序列化新的 `SectionSpan`；新消费者可使用完整有序区间。

## 验证边界

回归覆盖单篇 API、模型调用、全文与摘要来源、数据库及 JSON 往返、完整和部分覆盖、
预算及向量错误传播、SQLite 增量迁移、摘要尾部与缓存失效，以及章节与 Chunk 位置一致性。
这些用例不调用真实 Provider，不证明抽取准确率或综述成功。
本次保留 6000 字符块、8 次抽取默认值和统一研究 Runtime；Parent-Child、解析器替换、
能力分级检查及真实效果评测仍需独立实验与验收。
