# 多源检索的失败与执行边界

多源搜索通过同一线程池调用各数据源。一个来源失败，不应抹掉其他来源
或同源另一排序通道已返回的论文；取消、执行预算耗尽、租约失效和 CAS
冲突则属于整个执行的停止信号，不能降级成普通的 API 失败后继续请求。

## 请求与等待

每次 HTTP 尝试都先检查执行状态、源级熔断和冷却门；获取令牌后再次复核。
令牌不足时不发请求。令牌桶及退避等待以不超过 250ms 的片段检查取消和
执行期限。S2 仅在持锁时预留请求时刻，不在锁内睡眠，避免其他线程无法
登记冷却。arXiv 保留其原有全局请求间隔。

`Retry-After` 支持秒数和 HTTP-date。短等待可在次数和等待上限内重试；
429 在等待开始时就登记源级冷却，其他排队请求会看到该冷却门。超过本轮
可等待时间时立即退出当前来源，继续使用其他来源。服务端更长的重试期限
不会被本地冷却上限截短；冷却门只快速跳过来源，不占用线程整段等待。
未提供有效 `Retry-After` 时使用本地退避和冷却配置。

| 来源 | 请求边界 | 失败处理 |
| --- | --- | --- |
| Crossref | 搜索、DOI 详情共用 | 超时、连接故障和选定 5xx 有限重试；每次检查熔断 |
| OpenAlex | 搜索、work 详情共用 | 超时和连接故障有限重试；每次检查熔断 |
| Semantic Scholar | 搜索、详情共用请求入口 | 超时和连接故障有限重试；共享请求间隔和冷却 |
| arXiv | 请求入口统一控制 | 超时和短 429 有限重试；长 429 保留失败分类并登记冷却 |

429 不计入来源故障熔断。401/403 不自动重试、不计为服务故障；404 作为
未找到返回。其他 4xx 不盲目重试。网络故障与 5xx 的重试仍受动作执行期、
源级熔断和每次 HTTP 超时约束。

arXiv 仅在短语请求成功但结果为空时尝试松散查询。认证、网络、限流等失败
不会通过改写查询再次启动请求预算。令牌等待超时保留独立的
`RATE_LIMIT_WAIT_TIMEOUT` 分类；其异常仍兼容既有 `requests.RequestException`
捕获边界，不会发送未获令牌的请求。

## 并发停止与部分成功

`search_papers` 的检索取消作用域通过原有 `submit_with_context` 传播。
调度线程定期检查完成任务与取消状态；工作线程遇到执行控制异常时先
停止同轮请求，再把原始停止原因交给主线程。未开始的任务被取消，已经
运行的退避、令牌等待及请求间隔会在检查点停止，不遗留脱离执行作用域的
后台检索线程。这个局部作用域不修改父研究任务的取消回调。

已经发出的同步 HTTP 请求不能被 Python 强制撤回；停止与收尾仍可能等待
该请求的客户端超时。HTTP timeout 会按活动执行的剩余期限收紧，但不能
据此宣称对任意网络或浏览器操作实现了即时取消。CNKI 的页面加载仍受其
浏览器超时配置约束。

同源 relevance/date 通道无论以何种顺序完成，来源诊断均累计已返回数量，
同时保留失败类别与错误信息。故障优先级固定，避免完成顺序改变来源健康
判断；最终论文仍按配置来源顺序和通道顺序合并去重。

## 配置与验证

配置示例见 `.env.example`。Crossref 默认额外重试 2 次，OpenAlex/S2 默认
额外重试 3 次；arXiv 保持原有最多尝试 3 次的内部接口语义。各源的
`MAX_COOLDOWN_SECONDS` 限制本地兜底冷却，不覆盖服务端最早重试时刻。
这些限流和冷却状态目前只在进程内共享，不能作为多进程全局配额管理。

离线验证覆盖真实线程池、模拟 HTTP、可推进时钟、令牌等待取消、执行期限、
排队任务停止、短 429 恢复、长冷却、熔断期间停止重试、认证/404 分类和
双通道部分成功。实际结果记录于 `docs/change-log.md`；不以模拟测试替代
真实数据源或真实 LLM 的端到端验收。
