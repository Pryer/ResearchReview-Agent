# 草稿交付、任务配置与增量检索

新任务默认`draft_first`，可在请求中指定`delivery_mode="strict"`。Main提取主题和要求、选择动作及上下文；专业Agent只执行本次委派并返回结构化结果。一次研究动作成功提交后可确定性汇报，减少纯复述模型调用。历史任务保留原交付策略与累计用量。

## 草稿与正式正文

`publish_draft`由Main提出、Controller提交。来源身份、原文绑定、引用解析和实质正文预检必须通过。语义核验未完成、覆盖和篇数缺口可以交付带定位清单的草稿；已确认矛盾或身份错误必须修正。正式正文仍要求当前版本独立Check和全部正式门禁通过。Check不改写正文、不自行调度其它Agent。

公开结果分别记录`execution_status`、`stop_reason`、`delivery_status`、`verification_status`和`requirements_satisfied`。已合法发布的不可变版本不因后续优化失败而隐藏。Job轮询的`available_delivery`提供执行期间可读版本；正文、下载和会话恢复保持同一版本。新任务不能读取同会话其它研究目标的旧稿。取消或失权后禁止发布新版本。

## 配置与预算

Settings仍是唯一配置入口；新任务保存脱敏`effective_config`及来源、版本、指纹。显式CLI、进程环境、`.env`、默认值按此顺序覆盖。E2E不再暗改LLM超时。Main96轮，总模型请求1024，检索模型子预算512，总时限3600秒，抽取仍为8块。Main决策轮、动作、恢复和模型尝试分别计数；重试和备用模型实际尝试计费，恢复不清零。

收尾预留为64请求、250000 token、120秒、12个Main轮次，按材料规模提高token估计。触及软线回到Main选择写作、核验、发布或结束，触及硬线立即停止新请求。请求余额包含LLM和检索模型，token余额包含已用检索token及在途预留。草稿已经可写但研究无收益时给Main一次收尾机会，仍受同一硬预算和无进展上限约束。

空闲任务可通过`PATCH /api/reviews/sessions/{session_id}/configuration`显式修订。请求包含`expected_revision`和`values`，例如`{"expected_revision":1,"values":{"agent_main_max_rounds":96}}`。运行中、存在在途请求、版本已变化或额度低于已用时拒绝；累计消费和审计事件保留。连接串、凭证不能通过此接口修改。总请求0沿用无限兼容语义；任务恢复不会因进程默认值变化自动变成无限。

## 补检索与复用

最终查询在清洗、锚点处理之后再次去重；“检索增强生成”等术语不按命令前缀截断。Provider台账按来源、规范化查询、年份、通道、配额和分页参数记录成功、空结果与失败；成功查询复用，临时失败有界退避重试，Provider自身冷却仍有效。

定向补检索携带purpose、gap_ids和queries。总体主题与缺口分别评分，通过排名融合；缺口Query保留名额。初始专用精排窗口120，确认材料仍不足时允许按需扩大到240；语义筛选按批进行，达到确认材料余量后停止。未筛选尾部仍为pending。

候选池变化允许重算全局BM25/RRF；Embedding、Query+文本精排和语义准入使用已有缓存。Chunk字段精排复用同一ScoreCache。原文块抽取响应按原文、切分、Prompt与模型指纹复用，读取后重新验证连续摘录和Offset；失败记录不作为证据。PaperCard原文依赖与准入资格分开，资格变化刷新资格和下游授权，不因排名抖动重读全文。`ExtractionCoverage.remote_requests/cache_hits`区分新抽取和缓存处理。

## 验证口径

离线回归、冻结真实材料Writer/Check组件、新任务E2E、原生pgvector集成和独立人工验收分别记录。报告保存首稿时间、总用时、真实模型尝试、缓存命中、停止原因和交付等级；不把未交付旧运行与成功草稿直接计算同质量提速率。

首个满足本地预检的草稿通过现有Main策略handoff优先发布，再由Main选择继续优化或结束，避免已可读却反复补证。Main已明确授权的单动作可确定性派发，子Agent不能改写委派参数；专业工具内部的领域模型调用保留。执行期轮询只读取发布片段，不反复解析全文和计算PDF哈希。

执行调度失败且已有合法发布版本时，兼容结果仍为partial，独立execution_status保留failed和真实停止原因；不冒充正式完成。当前坏候选不覆盖已发布版本的正文、引用映射、书目及质量报告。同一版本后续被Check确认有矛盾时撤回其公开资格，另一候选失败则保留原有效版本。

软收尾时，专业Agent可以提交已完成的阶段结果，并以budget_low/degraded交回Main；仍执行相同字段权限、来源和CAS校验。检索模型子额度耗尽只阻止新的检索模型请求，剩余LLM额度保留给写作和核验；总请求、token、任务deadline、取消或失权仍是硬边界。

真实5篇任务发现正文后混入“生成诊断”和target_char_range，字数区间被误当成引用。写作Prompt现只要求正文，结构化状态由执行器独立返回；规范化仅去除正文末尾明确的执行报告，不移除或猜测真实数字引用。raw与normalized候选及规范化动作均保留。
# 2026-11-11 发布准入补充

发布和动作准入共用 publication_fingerprint。相同内容与公开核验状态已经发布时，publish_draft 从 Main 可选动作中移除；直接重复调用仍保持幂等。书目、核验结论或公开问题变化可产生新版本，随机报告ID不产生新版本。草稿与 final 仍分别满足原有预检和正式门禁。

final_requirement_met 是兼容历史数据的引用数量字段，不代表整体交付通过；正式交付须读取当前 Check、quality_gate 和 requirements_satisfied。执行 completed 与研究结果 partial 可同时成立。
