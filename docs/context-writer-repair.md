# 上下文连续性与写作候选修复

本轮复用 Main → 专业 Agent → Controller 的既有执行链。Main 继续以 goal、state、key_evidence、decisions、open_questions 五字段视图决策。

## 上下文生命周期

同一次委派内部保留 ReAct 消息与工具观察。再次委派时，新建当前对话，将旧轨迹归档到现有 Artifact Store；通过角色工作摘要继承结果和依赖变化。没有数据库的离线调用保留原轨迹用于测试和排错。

当前 completed_actions、last_task_result 和 execution_status 只反映本次委派的工具观察；上一委派结果只放在 work_context.prior_result。模型汇报与工具事实分开保存，未执行就求助会返回 delegated_action_not_executed，不能据旧记录声称完成。

角色工作摘要以研究任务身份隔离，包含上一任务结果、具体问题、证据/稿件依赖指纹，以及新增、变更和撤销字段。Search 保留查询与窗口；Analysis 保留字段覆盖；Writing 保留当前基稿、候选引用和核验问题；Check 保留版本绑定的检查信息，并独立检查当前材料。

Controller 强制传入年份、最低引用数、目标字数、显式约束和内部引用协议。Main 选择补充上下文。执行 task brief 会到达实际调用模型的工具路径，不能由 Subagent 的简短选工具理由替换。

未执行阶段使用 not_projected/not_planned/not_checked 明确标记；不默认写成0。Main在调用Writer之前就能从当前证据与ClaimPlan取得真实授权篇数和prewriting_ready，避免把尚未写作的有效引用数当成检索缺口。统计在副本上计算，不修改权威状态。

## 候选与授权

Writer 使用来源验证过的 ClaimPlan 授权投影，包含摘要 coverage 的原文、证据 ID、访问级别与允许表达。证据 ID 必须属于对应论文。裸原文 span、题名和检索排名都不构成事实使用授权。

候选保存在 writer_candidate 产物中，记录原始正文、规范化版本、阶段、输入指纹、验证结果与拒绝原因。收到整篇模型响应后先保存，再做转换和验证。分节写作由工作线程收集响应，在所属数据库线程统一写入审计，避免共享 SQLAlchemy Session 并发写。

首稿、修复、润色、分节写作及引用补写都留痕。失败长稿保留为隔离候选，不被两句边界模板覆盖。失败工具只提交追加审计，不提交未完成正文。候选选择不授予发布权限。

大纲、整篇与分节写作使用同一授权投影；分节兜底缺少中文事实时，仍向模型提供授权原文，不把边界模板标为已完成正文。

内部正文使用 [paper_id]；引用模块生成公开数字编号和参考文献。仅在当前输入内唯一匹配的短ID、强标识别名可规范化；编号必须对应本次提示词明确给出的可信标签表。未知或有歧义的引用保留并报错，不按猜测的论文顺序分配。显式总字数覆盖默认规格，多交付物按默认篇幅权重分配；未指定时保留默认规格。

## 恢复与发布

Writing 返回结构化 issues 和候选引用。Main 根据问题选择补检索、补抽、重新授权、改写或核验。恢复仍使用既有策略和共享账本，总请求上限保持 1024，每篇抽取仍最多 8 块。

只有实质候选进入新协议待核验状态。旧写作适配器缺少新诊断时仍必须交 Check，不因缺字段跳过检查。Check 通过后，Main 申请结束；Controller 检查当前文本、来源、约束和核验版本后才允许发布。

诊断与验收分开记录：离线回归、真实冻结材料的组件验证、完整 Agent E2E，以及人工事实复核分别报告。
