# 执行提交、恢复与缓存边界

纯检索任务明确说“最多 N 篇”时，状态栏和交付判定使用返回上限，去重后最多展示
N 篇；有明确下限时仍同时检查下限。检索列表展示已有作者和 DOI，未知值不猜测。
综述的最终有效唯一引用要求仍由原有 `required_reference_count` 与质量门禁约束。
明确单年（如“2020年”）按单年闭区间执行，不回退成默认近三年。
明确否定的写作请求不用于触发写作意图；显式仅检索不会因为论文题名带 review
而被改成综述。纯检索指定“标题为/严格等于”时，最终发布按题名的空白规范化和
大小写无关比较筛选，邻近论文只能留在候选池；无精确命中则报告未满足要求。

## 动作输入和输出

每轮五字段已包含最新研究摘要，`read_summary` 已从原生工具、JSON 工具目录及
动作注册表移除。无进展上限仍用于实际动作和被门禁拒绝的交付申请，不能通过
重复阅读同一摘要消耗决策额度。

权威状态仍由 Controller 持有，主 Agent 仍只接收五字段视图。专业任务从
`app/agent/action_contracts.py:CONTRACTS` 投影输入，新增字段默认不可见；字段类型来自
`ResearchAgentState`，不再为未声明类型的字段自动退回 `Any`。以下是主要读写依赖，
完整字段白名单以 `CONTRACTS` 为准。

| 动作 | 主要输入 | 可提交产物 |
| --- | --- | --- |
| `search_and_rank` | 目标、查询、筛选、既有候选和路线摘要 | 候选、排序、筛选和检索诊断 |
| `fetch_metadata` | 候选、排序、元数据和已有文档 | 元数据、受控 PDF 引用、解析资料、筛选结果 |
| `extract_paper_cards` | 元数据和解析资料 | 证据卡 |
| `validate_routes` | 证据卡、候选路线、分析约束 | 路线、归属、覆盖诊断和分类 |
| `cluster_papers` | 证据、路线、分类和恢复约束 | 聚类、分类、主题综合 |
| `plan_claims` | 证据、主题、路线和声明约束 | claim 计划、对齐结果和证据门禁 |
| `generate_deliverables` / `rewrite_sections` | 授权卡片、claim、写作计划、分配、现有章节、核验约束 | 正文、检查点、引用、逐句核验和质量状态 |
| `validate_result` | 正文、证据、声明和最终约束 | 核验结果、引用和交付门禁 |
| `targeted_search` | 检索、分析、写作和恢复输入的显式组合 | 有界补检索及其证据、授权、引用修复产物 |

每个动作还读目标与必要轨迹，写执行诊断。`targeted_search` 的既有实现确实包含
多个阶段，因此保留显式复合契约；它不是任意字段通行证。写作任务不读取原始
`parsed_papers` / `pdf_paths`。共享预算、主控上下文和任务历史由控制层管理，
专业任务不能直接提交这些字段。用户主题、显式年份、参考文献数等保护字段不可修改。

写作、改写和独立验证均可提交 `claim_alignment` 与 `claim_citation_consistency`，
因为写作动作内部也执行完整的写后校验。背景动态提纲只在本次写作计划编译中传递，
目标与比较维度进入 `WritingPlan`；临时提纲不写入全局状态，不复用旧状态中的提纲。
后台执行失败通过统一公开原因映射显示，内部字段和原始异常仅留在服务端日志。

任务结果在生成端和提交端各校验一次：动作/角色/任务身份、输入指纹、状态版本、
输出键、字段删除、字段类型；同一字段同时设置和删除也会被拒绝。引用资料还要
通过会话归属、动作允许的资料类型、角色权限和版本检查。

## 数据库事务与预算

Main 通过 TaskMainLoop 请求能力、目标和资源范围。服务端从 Profile 注册表确定角色并签发 Grant，四角色共用 DelegationRunner。Search 和 Analysis 可连续执行获准 Action，Writing 和 Check 直接投影动作参数。每步经 ActionExecutor 进入同一个 Controller 提交内核。ToolExecutor 校验外部能力并持久化回执。阶段结果以 DelegationResult 返回 Main，后续动作由新的准入检查决定。

Main五字段、局部PlanningContext和具体Action输入分别投影。规划摘要不包含完整原始资料；Handler只读取当前契约允许的字段和资源。委派计划、Invocation、观察游标和累计计数持久化。每个Action独立提交产物、观察、版本及lineage，证据变化在同一提交中撤销过期派生授权。

恢复先续接数据库中的活动委派，已提交动作不重放；进程退出后未知远程结果按uncertain处理。完成工具、满足阶段目标、通过Check和允许交付分别裁决。取消/失权终止观察只补内存，不能覆盖原异常或提交成功状态。

每次观察完整载荷均保存为受控归档。Compaction 后工作记忆最多 8 条、8000 字符，
并按真实输入预算进一步缩减；累计观察序号不随裁剪重置。新 Epoch 只重建结构化
语义历史，旧原生调用和思考协议留在归档。`recall_context` 按证据 ID/引用查询
当前轨迹可达历史，返回有界摘要；扫描不完整会明确标记，历史不授予当前证据权限。

持久化路径是 `ResearchConversationService.handle/revise`。执行期数据库对象通过
ContextVar 传播，不进入模型上下文。直接调用graph也建立持久化作用域；已有服务作用域时复用，预算与Artifact Store不会另起一套。

- `research_runtime`：会话租约、CAS 版本、取消位、最新状态和累计预算。
- `research_tasks`：动作幂等键、来源版本、运行/完成/失败/阻断/过期/取消/中断状态。
- `research_attempts`：每一次外部模型请求的预留和已知用量，包括重试与备用请求。
- `research_checkpoints`：不可变的已提交研究快照。
- `research_events` / `research_memory_cursors`：追加事件及增量摘要游标。

任务发起先落库，外部调用不占写事务。成功提交通过
`session + version + owner + unexpired lease + not cancelled` 条件更新；状态、
资料、任务完成记录、事件和预算一起提交或一起回滚。后台 job 的领取也使用
`queued → running` CAS，进程内 guard 不再是唯一的重复执行防线。

心跳只允许当前 Owner 在租约有效且未取消时续约，过期后不能自行复活。SQLite 的
续约、Snapshot 和公开结果保存使用 UPDATE 实际执行时的数据库墙上时间，避免
等写锁期间已过期却仍用旧时间通过条件。该机制不承诺跨主机时钟一致性。
辅助账本先用条件 UPDATE 锁定 Owner，再读写；新研究动作还检查有效期、取消位
和版本。已付费响应结算、失败清理和释放可在同 Owner 过期/取消后完成，但接管后
的旧 Owner 不能覆盖新执行账本；失权结果仍不能发布。

真实请求发出前预留预算，收到响应先记录用量，再做 JSON、工具参数、取消及期限
检查。因此解析失败、空内容重试、备用切换、取消后收到的响应都不能漏计。
失败任务保留已消耗预算；恢复不清零。若进程在请求发出后崩溃，无法确定服务商
是否已计费，该请求标为 `uncertain`，按原预留保守计入估算消耗，不伪装成真实
usage，也不自动重放原任务。过期所有者的迟到响应不能覆盖新执行的账本。

进程内展示指标与数据库预算账本职责不同。展示指标统计服务商实际返回的 usage，
预算账本还包含缺少响应时的保守估算，二者可以不同。缓存命中率分母使用已上报的
hit + miss；没有缓存数据时命中率为 `None`。这里不把 token 数伪装成供应商账单金额。

账本限制输入与输出总 token（含缓存命中），不是折算金额。当前没有已验证的
服务商 tokenizer，预留使用请求 UTF-8 字节数加协议余量及完整 `max_tokens`，
不使用字节除三、平均输出比例或缓存 EMA 折扣。该估计有意偏保守；实际 usage
先结算再检查超支/取消/期限，越界响应不会继续解析和用于提交。缺少 usage 或
崩溃未决的调用按完整预留估算。服务商若返回异常大用量，已发生费用无法撤回。

预留序列化使用紧凑 JSON，只移除容器格式空白，保留消息正文中的空格、换行和
引文。账本中的 `last_token_reservation` 记录输入上界、完整输出上限、估算方法
及服务商已报告的输入用量；未知用量保持 `None`。并行/嵌套请求各自关联响应，
较早请求的迟到响应不会覆盖较新请求的诊断。这项调整不采用按语言比例折算或平均
输出预留，也不代表已测得中文 Token 或完整任务成本的固定节省比例。

新会话默认上限为 `10000000`（一千万 tokens），已有账本保留原额度。管理员可对空闲会话显式更新：

```bash
python scripts/update_session_budget.py --session-id YOUR_SESSION_ID --expected-limit 1000000 --token-limit 10000000
```

该操作通过数据库 CAS 校验原额度、版本、账本及执行占用，拒绝活动任务和未决请求，
不清零用量、不接管租约、不启动研究；变更记录在事件表。随后仍需显式检查点恢复。
读取会话时独立刷新账本，即使研究检查点版本不变也能取得最新额度。

公开停止原因区分 token 预留不足、实际超支、次数额度、执行超时和无进展。
字符串错误可安全处理，内部异常文本保留在诊断记录，不原样拼入用户回复。
预算、取消、失权及账本冲突优先于质量门禁显示；证据缺口和质量诊断仍保留在门禁报告中。
大纲、引用分配、引用回填、章节写作及生成包装入口共用 `is_control_exception`，
这些停止信号不能进入确定性 fallback、章节重试或普通模型失败包装。

全文重建会在清除当前正文与授权前保存 `quarantined_generation_snapshot`，
记录上一候选的正文、引用、主张授权、验证报告、证据版本及来源资料引用。
该候选用仅 `service` 可读的独立资料类型进行 JSON 分片持久化，重启后仍可恢复审阅；
当前任务不读取它，也不把旧授权或旧计数带回新证据版本。空候选或写作前阻断说明
不能覆盖上一份真实草稿。公开结果只提示历史候选存在，公开正文仍须通过当前门禁。
此机制保护后续重建；修改前已清除的当前稿件仍需从其原有历史检查点审阅恢复。

公开会话保存也验证租约和版本。取消与提交由数据库写入顺序裁决：取消先提交则
研究结果无法随后提交，但已发生的消耗仍结算。旧后台 worker 的取消异常处理
不能覆盖新执行。已发出的外部请求仍依赖客户端超时/协作取消，不宣称远端立即停算。

## 历史与恢复

会话历史在展示窗口保留最近 50 条之前逐条归档。条目标记避免重复保存，但相同
文本的不同新消息仍保留各自发生次数；归档内部键不会经会话历史 API 输出。
旧会话用数据库事件标记执行一次迁移，过去已截断的历史不能凭空恢复。

摘要从已提交游标之后读取新事件，摘要资料和游标在调用方同一事务保存；问题解决、
决定失效不会因再次摘要而复活。原始事件始终保留，摘要只是可重建视图。

会话读取会优先恢复比公开会话更新的已提交研究检查点，并从账本恢复最新消耗。
Pydantic 诊断保存为结构化字段；大型任务补丁按 JSON 片段保存并原样恢复，
不靠字符串化对象或截断证据避开资料大小约束。

对 `running/failed/cancelled/blocked` 的中断会话，可通过原 Agent 请求 API 显式发送：

```json
{
  "session_id": "原会话 ID",
  "user_query": "继续上次研究",
  "resume_from_checkpoint": true
}
```

恢复保留原研究目标、证据、年份和篇数要求，开始一个新的操作序号，交由主 Agent
重新决定未完成工作。待澄清会话仍走澄清回答，已完成会话仍走修订入口。崩溃进程的
租约到期前不能被另一个执行抢占；重启不会假定所有其他进程都已死亡。没有已提交
检查点、资料损坏或缺失会明确报错。恢复不绕过质量门禁，也不会自动提高预算。

启动队列恢复将中断的 Job 标为 `failed`、待取消的 Job 标为 `cancelled` 时，
在同一事务内同步其仍为 `running` 的会话状态，不改研究快照。若已有较新 Job、
同时间戳导致归属不明确，或会话已经结束，则保留会话状态；任一写入失败时整体
回滚。该逻辑沿用现有队列的启动恢复语义，不撤销 Runtime 租约，也不提供新的
多进程队列接管机制。

启动时 `init_db()` 会添加上述新表；也可运行
`python scripts/migrate_agent_runtime.py`。迁移幂等，不删除旧表、历史或研究资料。
更新后需重启服务；本次开发未替用户重启正在运行的服务。

## 提示词与章节复用

证据卡、章节改写和完整交付物写作提示词均采用固定规则/输出结构在前、动态研究
材料在后。原生工具请求只通过 `tools` 发送工具目录，JSON 回退仍携带文本工具目录。
规则、输出约束和引用核验保留，不以删证据提高命中率。

章节指纹与渲染共用授权投影和 claim 约束匹配。复用判定前生成确定性证据草稿，
覆盖实际原文、授权后的本节卡片、主题/范围/重点、引用政策、路线、分配、筛选、
末路线综合义务，以及真正注入每一节的授权综述清单。无关论文和单纯全局快照变更
不会无故使全部章节失效。旧指纹因 schema 变化自动失效。

这些改动改善应用复用和服务商前缀缓存条件；没有在客户端实现模型 KV cache。
真实命中率以返回的缓存字段为准，单次验收不是相同质量下的节费对照实验。

`LLM_REASONING_MODE=static` 遵守 `LLM_THINKING_ENABLED`；关闭时章节写作和引用
补写不额外开启思考，也不因此扩大输出预留。`auto` 及显式单次调用覆盖仍生效。
服务商报告的 `reasoning_tokens` 作为 completion 的子集保存到请求账本，不重复
加入总 token；未报告时不填零。失败请求缺少 usage 的保守估算仍单独标记，
账本累计用量不等同于服务商实际扣款金额。

服务商返回余额不足（HTTP 402）后，本次执行跳过该账号并尝试可用备用服务。
配置的服务均不可用时抛出不可继续的模型服务异常，验证、改写和门禁不得吞掉并
继续发起调用。短路记录仅属于本次执行，新执行可在充值后恢复。后台返回 failed
结果时也保存安全的用户错误说明；前端读取旧任务时可从结果错误重建说明。

### 篇幅与段落验收

`writing_plan.py` 将显式 `target_length` 按各交付物默认篇幅权重分配，形成各份
`WritingPlan.target_char_range`（当前为分配目标的 80%—120%）；交付物内部再按
章节权重分配 `target_word_count`。字符区间属于交付物级，不是每个章节都存一份
相同的总目标。

模型自报字数不作为验收依据。`strip_writer_report` 清理正文后带明确标记的执行
报告，并保护后续真实学术章节；`validate_deliverable` 自行统计自然段，以及去除
引用标记、空白等后的正文字符数。当前研究背景规格为 **3—5 个自然段**，违反段数
要求会产生错误；带证据下限契约的路线章节也检查最低正文量。

整体 `target_char_range` 超范围目前只产生警告，不会单独令验证失败。段落/结构或
路线正文底线失败进入既有候选修复、Main 恢复和质量门禁，是否继续及采用何种
改写受证据、恢复次数与预算约束；不承诺每次篇幅偏差都会自动局部重写。本次没有
改变这些验收规则，也没有将未知的用户段数要求自动解释为规格参数。

## 验证入口

研究记忆现由 Main Agent 按任务调用 `search_research_memory` 查询，摘要引用实际参与
会话/角色/类型校验和加载；结果有界注入状态栏，不自动灌入整份历史。当前决定和问题
以最新摘要为准，旧摘要只召回历史发现；最近失败事件可按任务查询。明确采用反馈与
后续动作结果分别记录为幂等事件，并随状态恢复；未反馈只记录已呈现，不宣称已使用。
当前只做同会话词项检索，扫描有上限且显式报告不完整。工作摘要优先保留少量未恢复
失败，不能突破总预算；历史不能授予当前证据权限或改变质量门禁。协议和配置见
[研究记忆检索闭环](agent-context-architecture.md#research-memory-retrieval-loop)。

`tests/test_section_checkpoint_fingerprint.py`、`tests/test_cache_usage_boundaries.py`、
`tests/test_action_contracts.py`、`tests/test_durable_runtime.py` 和
`tests/test_research_memory.py`、`tests/test_research_memory_retrieval.py` 覆盖复用、记账、越权补丁、真实 SQLite 并发 CAS、
提交故障回滚、崩溃未决请求、取消/迟到响应、迁移、历史游标和显式恢复。
本轮全量结果及真实 CNKI/LLM 验收结论见

## 元数据变化后的证据卡重建

Controller 在 `fetch_metadata` 提交内比较详情变化并撤销旧证据授权。比较保留论文内容、
身份、来源和语义准入字段；排序分数不属于证据内容，缺省来源集合与仅包含主来源的
集合等价。新增来源、摘要/身份/年份变化、准入置信度或交付资格变化仍按失效处理，
未知字段变化也不自动忽略。此规则不删除来源溯源字段。

已有卡片失效后，`pending_card_rebuild_ids` 记录当前详情中缺失的卡片。该字段与详情
在同一 Controller 提交和检查点中保存；旧任务恢复执行后同样优先交回 Analysis Agent
执行 `extract_paper_cards`。Search Agent 可以汇报并归还控制权，不能越权提取。
这是局部证据依赖交接，用户改约、必做恢复队列、取消与总预算仍由原执行边界约束。

重建复用仍有效的卡片，仅提取缺失部分；成功提交当前卡片后清除对应标记。提取卡片
不会恢复旧主张、路线或写作授权，仍须执行规划和质量门禁。纯论文检索任务不会因为
这项交接自动转为写作任务。提取失败仍保留待重建项，并服从既有无进展与预算上限。

写作前 readiness 与写后数量门禁的结构化恢复建议使用现有约束授权策略：明确禁止
扩大年份或降低最低引用数时，不返回对应建议；用户明确改约仅解锁已记录的维度。
问句、API 的结构化字段与实际执行权限须分别保持一致，建议本身不授予执行权。

2026-10-23 的保存状态离线重放表明：历史一次详情变更后5张卡全部失效，修复后保留
1张未发生实质变化的卡，并安排其余当前卡片重建。这不是已证明的有效引用或真实
正文成功，也没有测量实际Provider延迟、成本或成功率收益。本轮真实额度不自动续增。


## 失败审计、任务历史与进展摘要（2026-11-14）

专业动作仍通过 build_task_state 按契约深拷贝输入，Handler 不直接持有父研究状态。执行完成后的取消会拒绝业务补丁，已发生模型消耗仍保留在账本；Controller 的执行状态和计划状态属于生命周期记录。

写作普通异常中的追加候选审计在 Controller 内立即持久化：未合并失败补丁的父状态、失败任务状态、累计预算与检查点通过同一次版本/所有权/取消/租约 CAS 提交。数据库写入失败会整体回滚，无需等待子循环的后续收尾检查点。取消或失权后不能用审计路径绕过提交限制。

持久化 Controller 的 agent_task_results 保留最近 16 条供上下文读取；完整成功结果保留在 research_tasks，按会话与唯一 idempotency_key 查找，失败审计提交时也保存对应结果。没有持久化 runtime 的纯内存模式保持原有历史与幂等行为。历史大列表恢复后会在下一次新结果提交时收敛到近期窗口，旧快照的读取格式保持兼容。

进展摘要对卡片、路线与主张使用内容摘要，避免将整段原文再次嵌入外层 JSON。主循环运行期缓存上次独立内容快照及摘要，未改变内容时复用；嵌套 Span 原地变更仍触发重算，集合顺序变化不算进展。缓存以 ContextVar 隔离，不进入状态快照，运行结束后释放；单集合最多缓存 512 项。此处不直接使用 artifact_manifest 版本，其他源状态/安全指纹仍按原语义校验。

本地合成测量：60 张卡片 × 40 个 Span，每批 25 次、重复 3 批取中位数，缓存路径先预热一次。仅 progress_fingerprint 的单次时间从 19.49 ms 降为 0.18 ms；该测量不是完整任务、模型成本或变更密集路径的性能结论。回归覆盖数据库重开审计、事务回滚、近期历史与完整结果查询、取消隔离、嵌套修改及排序稳定性。


## 新研究与恢复的预算边界（2026-11-14）

同一会话在 completed、partial、failed 或 cancelled 状态下通过普通 handle 请求开始新研究时，重置该研究的决策轮数、检索轮数、恢复次数、专业动作数与执行期限。会话累计 LLM/检索模型Token、请求数、额度及未决费用不清零。领取Owner的事务先结算旧未决调用，再重置工作计数并保存 prior_task_usage 汇总；外层只提前初始化新期限，避免旧期限在领取前拦截新研究。

显式检查点恢复、澄清、论文集合修订以及 blocked 任务的质量恢复继续沿用原任务计数与预算。新研究递增已有操作序号，使同主题的新研究也不会误用上一任务的幂等结果。该边界不提供额外Token或请求额度，也不解除任务原有约束。

retrieval_screening_cache 现在按 execution_cache 类型分片外置，恢复兼容旧的内嵌字典；筛选命中刷新字典顺序，在1024项容量下按最近使用保留热点。完整工作状态和API可编辑研究状态均保留该缓存，内容/范围/模型依赖仍由原缓存键校验。


## 架构v2迁移中的接入边界（2026-11-17）

`build_research_actions`提供生产和离线验证共用的业务Handler与交付验收器。`run_search_delegation`是显式的任务级Search服务，必须处于独立durable_scope；它不占据Action task_scope，每一步经同一个Controller独立提交。

活动委派和Invocation保存在数据库中；状态中的active_delegation_id用于恢复定位，已提交委派汇总可以重读。生产旧Main已退役。已知历史活动记录通过目标/来源指纹及提交证明迁移；未知格式明确拒绝，不能只改architecture_version标记绕过迁移。

启动迁移登记Agent Schema版本并验证结构，SQLite用短BEGIN IMMEDIATE事务串行升级。备份回退仅在停写副本演练，不提供运行中的逆向删表操作。完整验证与剩余工作见[重构执行记录](validation/2026-11-17-architecture-v2-s0.md)。

### 任务级Main、局部策略与观察提交

新任务通过 TaskMainLoop 选择研究能力，默认局部策略为 deterministic（v2-B）。历史快照在完整参数校验通过后记录架构升级，保留原模型、交付策略、约束和累计预算。旧 .env 若显式配置 v1，应移除该值或改为 v2。

当前指定恢复动作使用single_action，只有服务端能够签发，绑定唯一Action及不可变参数；legacy_single_v1只保留历史迁移/回读语义。两者共用精确单动作授权与direct执行。完整退役与本地清点见[运行器退役记录](validation/2026-11-18-v2-runtime-retirement.md)。

`AGENT_V2_LOCAL_STRATEGY=deterministic|react` 控制 Search 与 Analysis 的局部决策；`AGENT_V2_ANALYSIS_STRATEGY=inherit|deterministic|react|plan_and_act` 可单独选择 evidence_build 策略。模型计划在执行前校验全部步骤的静态参数，第一步需当前可执行；以后各步继续检查最新授权和输入版本。计划、游标与策略模式持久保存，恢复不重新规划已提交步骤。

Writing/Check 始终走 direct 薄路径；章节修订绑定当前已知且获准的章节，单次最多三章。候选提交后进入独立 Check 门禁。Check 任务的 satisfied 表示核验执行完成，正式交付仍检查报告判定和原 finish_validator。

委派结束时，Main 的 delegate_agent 观察与活动标记清理写入同一快照。提交前崩溃保留标记并重读已完成汇总；提交后恢复已有配对观察，不重放专业动作。Main 同步记录任务决策及五字段报告快照。授权拒绝和业务执行异常分开处理；取消/失权的终止观察仅修改内存。

当前验证和未闭合项见[四角色与任务级Main接入记录](validation/2026-11-17-v2-role-main.md)。工具级全量治理、精确资源lineage、历史活动子Agent迁移及API/报告/前端完整展示继续实施。

### v2工具回执与既有费用账本

专业 Handler 的外部能力现通过 `ToolExecutor` 执行，工具依赖由 `ActionSpec.tool_dependencies` 声明。每次调用重新读取活动 Grant、Invocation、研究 Task 和业务版本，start 持久确认后再检查取消/租约并执行。调用回执不推进研究业务版本或快照版本。

模型仍由原 `budgeted_create` / retrieval HTTP 账本计费，工具层只关联身份和审计，不重复收费。Worker 回执沿用线程内 Session 与串行短事务。接管时，缺少终态的工具 start 标为 uncertain；失败回执只表示调用抛错，不能据此推断免费或无外部执行。

检索、详情、PDF、模型和向量快照已接入；Artifact/候选的后续接入见下节。该批范围、控制异常修复和验证见[工具边界记录](validation/2026-11-17-v2-tool-boundary.md)。

### Artifact输入scope与候选暂存lineage

Artifact和候选读写现已接入v2工具层。Controller创建Task时，按Action输入契约和实际角色冻结资料引用；工具不能通过猜测ID、替换state或传入service角色扩大读取范围。业务Artifact写入同Attempt暂存lineage，正式输出lineage与Action结果、业务版本和检查点一起提交。

并发候选存取经PersistenceWriter使用线程内Session，v2路径不再flush父Session。暂存审计不成为证据授权或发布结果；独立Check与交付门禁继续执行。当前按Artifact引用精确控制，论文/文件级Grant scope继续实施。范围和回归见[Artifact与候选lineage记录](validation/2026-11-17-v2-artifact-lineage.md)。

### 论文参数与可观测进度

Action输入现同时绑定论文标识、下载元数据、文件哈希和向量来源。详情补全、下载与解析的可信回执可扩展同Attempt范围；更换PDF后旧正文source失效，必须匹配解析结果后再访问相应向量来源。显式paper_ids子集Grant的局部抽卡范围见下节。

Job查询兼容增加execution_progress，按实际owner范围汇总委派/动作/工具计数，避免串入后续运行。v2前端显示动态计数；运行报告记录任务分组、工具回执和失败尝试，不为未提交动作补造提交版本。实现范围和测试见[论文文件范围与进度](validation/2026-11-17-v2-paper-scope-progress.md)。

Job绑定同时记录任务配置中的架构版本，所以主控在第一次委派前澄清或停止时，v2仍显示动态计数。终态清空当前角色/动作展示，后台残留的running任务行仅供恢复诊断。工具的completed、failed、uncertain和pending分别计数；接管产生的uncertain回执仍归属于原工具调用所在执行，报告与轮询共用原事件范围，不把未知结果当成成功或免费。

聊天完成消息通过统一投影保留delivery_status、verification_status、requirements_satisfied、draft_released和发布版本。取消/失败后只从服务端available_delivery读取已发布正文和该版本参考文献，不从失败结果提取候选稿；执行终态与交付等级分别保留。澄清问题仍可回答，已发布草稿可同时阅读和下载。下载需要非空正文与已发布标记，不构成新的发布授权。实际路由/组件验证见[产品交付记录](validation/2026-11-18-v2-product-delivery.md)。

### 已知旧委派与局部抽卡

显式进入v2后，已知v1活动委派可转换为精确single授权；已经数据库证明的提交只导入结果，不重新执行。未知格式、目标不符或提交歧义保持拒绝；旧Analysis核验转Check复验。迁移写入复用同一CAS快照，并强制读取最新业务版本拒绝并发覆盖，旧费用、轮次和审计保留。

evidence_build的scope.paper_ids现支持局部卡片重建，按ID合并并保留其他论文和待办；提交后交回Main检查全局授权。该范围不能消费全局mandatory动作或降低用户引用约束。支持格式与剩余范围见[迁移与子集记录](validation/2026-11-17-v2-migration-subset.md)。

### 角色模型与上下文身份

`AGENT_ROLE_MODEL_PROFILES`按Main/四角色选择已有主备通道、模型和参数，默认继承全局配置。配置纳入任务快照；缺少此字段的旧快照使用空配置。委派保存模型、提示和窗口身份，恢复时拒绝混用不同配置。Check配置进入核验指纹，旧模型结论不会自动沿用。

PlanningContext携带最新业务版本与来源指纹；Action简报区分委派、逻辑动作、执行尝试和数据库Task，输入权限继续由原契约裁决。每次实际模型请求前核对完整消息和最终输出额度，包含备用切换和扩额重试；超限原样传播，保留已发生费用。字段及验证见[角色模型与上下文](validation/2026-11-17-v2-role-profiles.md)。

### 章节计算缓存和修订时限

v2分节写作将局部结构校验合格的章节保存为内部计算Artifact，确认落盘后可跨进程恢复。复用要求目标、基稿、计划、章节授权/证据、提示及模型策略指纹一致；缓存命中仍重跑局部检查，完整候选继续一次提交并交Check。缓存不成为公开正文或事实授权。

`AGENT_SECTION_REVISION_TIMEOUT_SECONDS`默认300秒，限定每次修订Action尝试，包含Sidecar与Worker，并取剩余全局期限的较小值。请求超时随剩余期限收窄；Controller正式快照前检查，超时不提交候选，费用与已保存计算缓存保留。协作式边界和验证见[章节恢复记录](validation/2026-11-18-v2-section-recovery.md)。

### 竞态验证与领取时钟

租约领取现与续约/提交采用相同的SQLite执行时钟，资格判断与新期限不复用等待写锁前的Python时间。固定三类各100条屏障调度覆盖取消/提交、接管/提交及ACK/中断，核对已知费用、未决预留、重复回执和已提交动作恢复。清单与有限覆盖范围见[竞态矩阵](validation/2026-11-18-v2-race-matrix.md)。

### 业务控制与发布恢复

v2主控每轮沿用原收尾预算和记忆准备，澄清输出遵守服务端kind/needed契约；发布预检拒绝交回主控继续规划。Controller将发布版本和publish_draft观察在同一快照提交，观察在CAS前只存在于候选内存，不另写成功归档。提交前后恢复均不会留下未配对调用或重复发布版本。

冻结合成材料通过实际写作、引用、独立Check和最终门禁运行；完整范围见[业务闭环记录](validation/2026-11-18-v2-business-flows.md)。真实来源、模型质量与策略收益仍须单独验收。
